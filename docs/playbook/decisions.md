# Decisions (method)

The "why" behind the playbook. Product and tech decisions of an app live in that app's repo (`docs/decisions.md`), not here.

**Newest wins.** If two rows disagree, or a row and another page disagree, the newer row wins. Fix the older page; mark the older row `replaced by #N`.

**Who decided.** `Sebastian (date)` only when he said yes. Everything else is `suggested` (by Claude or a review). A suggestion never turns into a decision by being written down.

**How to add a row:** only after a retro, in one session (#20, #35). Newest number at the bottom. "Why" is 2 to 3 lines with the evidence. If a row replaces an older one, write the old number in "Replaces" and set the old row's status to `replaced by #N`. Never delete rows.

**v3 note (28 Oct 2026):** rows 1 to 23 were suggestions nobody had used yet, so v3 edited some of them in place (marked **v3**). **v3.1** (same day, after a fact-check, a pre-mortem and a second walkthrough) fixed wrong facts in place and added rows 38 to 48. From now on the rule above holds: add rows, never rewrite them; until the first retro of the next app, only broken facts (#43). **28 and 29 Oct 2026:** deliberate exceptions by Sebastian (#49, #51, #52); status cells of the rows they replace were updated. The playbook now lives in the template repo (`docs/playbook/`).
