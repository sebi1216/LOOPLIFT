# Troubleshooting

**Rule: real incidents or tested failures only.** A row goes in the first table only after something actually broke (say where) or a reviewer reproduced it (marked "tested in sandbox": Linux, not yet seen on Windows). Known traps from official docs wait in the second table until they happen to you. Facts and sources for the fixes are in `reference.md`.

## Real incidents and tested failures

| Symptom | Cause | Fix | Seen in |
|---|---|---|---|
| Expo Go on the iPhone won't open the project, or says the SDK is not supported | The store Expo Go supports one SDK, and in 2026 it often lagged behind a new SDK (SDK 56 only in a TestFlight beta in May (E); 57 came about 2 months late). Clou was on SDK 58 while the store app was on 57 | 1. Check the App Store listing "What's New" (trust it more than expo.dev/go or Expo's troubleshooting page). 2. If the store is behind and you can wait: web + Android emulator for now. 3. Way out: Apple Developer Program + development build or `eas go`. 4. **Fallback pin recipe** (tested in sandbox 28 Oct 2026, SDK 58 to 57): ask Claude to read versions with `npm view expo-template-default@sdk-57 dependencies`, set them in `package.json`, set `jest-expo` and `eslint-config-expo` to `~57.0.0`, delete `package-lock.json`, `npm install` (about 2 min), change the native tabs import to `expo-router/unstable-native-tabs`, then `npm run check`. `npx expo install --fix` alone fails on a downgrade. Upgrade back once the store moves | Clou repo on SDK 58 vs store Expo Go 57 (review 28 Oct 2026). Today the store runs 58 (58.0.5), so this is only a fallback |
| F5 in VS Code waits forever on "dev server"; the phone-sized Chrome never opens | The old setup used a VS Code task that waited for text Expo prints only outside an interactive terminal | The starter no longer uses a task. Start `npm run web` yourself, wait until the terminal shows http://localhost:8081, then F5 (`.vscode/launch.json` only opens Chrome). Or skip VS Code: Chrome on http://localhost:8081, Win+Right | Clou, 27 Oct 2026; cause confirmed in Expo's source (walkthrough, tested in sandbox) |
| "CommandError: Port 8081 is unavailable", or the preview opens on 8082 | A dev server you started yourself (or an old Clou server) still holds 8081; Desktop then moves to the next port. Normal on purpose: when Claude's preview holds 8081, your own `npm run start` for the iPhone takes 8082 | Before Claude starts the preview, stop your own server (Ctrl+C in its window). Find a stuck process: `netstat -ano \| findstr :8081`, then end that PID in Task Manager. Web tests use their own port 8099; if 8099 is busy they stop with an error | tested in sandbox, 28 Oct 2026 |
| No QR code when Claude or the Desktop app started the server | A server started without a terminal prints only "Waiting on http://localhost:8081", no QR | For the iPhone, run `npm run start` in your **own** PowerShell window; the QR shows there | tested in sandbox, 28 Oct 2026 |
| `npm ci` shows yellow `npm warn deprecated` lines and "16 vulnerabilities (13 low, 3 high)" | Comes from Expo's own build tools (`zod` via `@expo/cli`), not your app code | Normal. **Never run `npm audit fix --force`**: it installs expo@51 and breaks the app. Plain `npm audit fix` is no better: it rewrites `package-lock.json` and fixes none of these. Check with `npm audit --omit=dev --audit-level=high`, ask Claude whether each high is in shipped code or only a build tool, wait for an Expo patch and run `npx expo install --fix`. Red `npm error` lines are a real problem | tested in sandbox, 28 Oct 2026 |
| `.npmrc` `min-release-age=7` seems to do nothing, or `npm -v` still shows the old version after an upgrade | Needs npm 11.10+; npm 10 ignores it silently. On Windows the Node installer puts `Program Files\nodejs` before `%AppData%\npm` on PATH, so the old bundled npm keeps winning ([npm docs](https://docs.npmjs.com/try-the-latest-stable-version-of-npm)) | Optional: `npm install -g npm@11`, reopen PowerShell, `npm -v`. **Never `npm@latest`** (npm 12 needs a newer Node). Still old: don't fight it; the delay is off and CLAUDE.md rule 3 (package at least 7 days old) is the stand-in | tested in sandbox, 28 Oct 2026 |
| First commit fails: "Author identity unknown *** Please tell me who you are" | New PC, no git identity; `gh auth login` does not set it | `git config --global user.name "<Your Name>"` and `git config --global user.email "<GitHub noreply address>"` (GitHub > Settings > Emails) | tested in sandbox, 28 Oct 2026 |
| A blocked command still ran (for example `git push -fu` force-pushed) | The guard hook and deny rules match text, so creative bypasses get through (current count: see the starter's test output, `npm run test:hooks`). A crashed or timed-out hook used to let the command through | Use the stricter fail-closed guard with `"onFailure": "block"`. Do not treat the guard as a wall: keep the allow list exact, keep production secrets off the PC, run unattended work in the cloud. Safety test counts only if you see the hook's own message ("Blocked by .claude/hooks/guard.mjs"), not a polite refusal by Claude | tested in sandbox (engineering review), 28 Oct 2026 |
| Jest runs every test twice and warns "Haste module naming collision" | A worktree in `.claude/worktrees/` is swept into Jest, tsc and ESLint | Exclude `.claude/` in the Jest, tsconfig and ESLint settings (starter does this) | tested in sandbox, 28 Oct 2026 |
| Figma MCP stops answering after a few calls | Starter (and View/Collab) seats allow 20 MCP calls per month | Don't design in Figma on a free seat. Full seat for design months (200 calls/day), or code-first / Claude Design. https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/ | Clou, Oct 2026 |
| Many `claude/...` branches and PRs, merge conflicts, you merge by hand | Several writers: cloud sessions (each pushes its own branch), Claude Code in VS Code, Dependabot | One writer per repo. Delete stale branches (`git branch -r`, then delete on GitHub). Night work ends in one PR that the main session merges | Clou, 26 to 28 Oct 2026 |
| CI lint fails or Expo complains about versions right after a bot PR | Dependabot version updates bumped eslint to 10 and React to 19.3.1; Expo pins its own versions | Revert the bump. Version-update PRs off, security alerts on. Update on purpose with `npx expo install --check` (then `--fix`) | Clou, 28 Oct 2026 |
| Text cut off in the design file after import ("HEART RAT") | FigCraft import kept full font sizes inside scaled components (944 texts) | Rescale the texts. Never scale components, make a size variant | Clou, FigCraft, 28 Oct 2026 |
| `git worktree` folder can't be removed; Git lists an old worktree | A Node process from a review session still held files | Close the process (Task Manager, `node.exe`), then `git worktree prune` | Clou, 27 Oct 2026 |
| `/kickoff` stops: "`git status` must be clean", right after installing the Expo plugin | `claude plugin install ... --scope project` rewrites `.claude/settings.json` (same content, keys reordered) | Run `git restore .claude/settings.json` yourself, then install with `--scope local`, which leaves the repo unchanged | tested in sandbox, 28 Oct 2026 |
| A harmless commit is "Blocked by .claude/hooks/guard.mjs: touches a .env file" | The guard matches text: any command that mentions `.env`, for example a commit message "docs: explain .env handling" | Reword the message ("env file"). Don't loosen the guard | tested in sandbox, 28 Oct 2026 |
| `npm ci` prints `eslint@9.39.5: This version is no longer supported` | Expo's lint config pins it | Ignore; never upgrade eslint by hand | tested in sandbox, 28 Oct 2026 |

## Known traps on Windows (from docs; move up when it happens, delete if day 0 passes)

| Symptom | Likely cause | Fix to try | Source |
|---|---|---|---|
| "'gh' (or 'node', 'claude') is not recognized" right after installing | The open terminal still has the old PATH | Close PowerShell and open a new one after every install. The Claude desktop app reads PATH only at start: quit and reopen it | https://code.claude.com/docs/en/setup.md, https://code.claude.com/docs/en/desktop.md |
| "npm.ps1 cannot be loaded because running scripts is disabled on this system" | Windows default PowerShell execution policy | Once: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` | https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies |
| Expo Go on the iPhone asks you to log in, or won't load the project after the QR scan | iOS needs a login in **both** the Expo CLI and the Expo Go app | `npx expo login`, check with `npx expo whoami`, then sign in to Expo Go with the same account | https://expo.dev/changelog/expo-go-57-login |
| QR scan does nothing; phone can't reach the PC | Windows marked the Wi-Fi as Public; firewall blocks Node; campus, dorm or hotel Wi-Fi blocks device-to-device traffic | Settings > Network > your Wi-Fi > **Private**; allow Node.js on private networks. Still nothing: iPhone hotspot for the PC, or `npx expo start --tunnel` (SDK 58 tunnel, no ngrok) | https://expo.dev/changelog/sdk-58 |
| "Filename longer than 260 characters" | Only when building Android **locally** (`npx expo run:android`) | Keep the project in a short path like `C:\DEV\app`; or enable `LongPathsEnabled`. `git config core.longpaths` does not help | https://docs.expo.dev/troubleshooting/windows-long-paths/ |
| Emulator tools: "adb not found" or `ANDROID_HOME` not set | Set only in a PowerShell profile, which Desktop ignores | Put `ANDROID_HOME` and platform-tools in the Windows **user variables**, then restart PowerShell and the app | https://docs.expo.dev/workflow/android-studio-emulator/ |
| Android emulator very slow or refuses to start ("acceleration") | Windows Hypervisor Platform (WHPX) off; old AEHD driver ends 31 Dec 2026 | Virtualisation on in BIOS, "Windows Hypervisor Platform" in Windows features, restart | https://developer.android.com/studio/run/emulator-acceleration |
| Desktop Browser pane stays empty or "server failed to start" | How Desktop starts `npm.cmd` is not documented; or port 8081 in use; or Desktop doesn't see `node` | Close other servers; set PATH in Windows variables and restart the app. Still failing: `npm run web` in your own PowerShell and plain Chrome on http://localhost:8081 | https://code.claude.com/docs/en/desktop.md |
| Every shell command says "Blocked" or "Safety check" failed, even `git status` | The guard fails closed: if `node` can't start or the hook can't read its input, the command is blocked. Most likely the desktop app started before Node was installed, so it has no `node` on PATH | 1. New PowerShell: `node --version`. 2. Quit the Claude desktop app completely and reopen it (it reads PATH only at start). 3. In PowerShell in the repo: `npm run test:hooks`. Green there but still blocked in the app: `claude` in PowerShell, then `/hooks` to see the error. Don't delete or loosen the guard; park it in `docs/now.md` and continue tomorrow (4-hour rule) | https://code.claude.com/docs/en/hooks.md, https://code.claude.com/docs/en/desktop.md |
| `/code-review` asks for a pull request | A synced plugin skill (`code-review@synced`, "review a pull request") answers instead of the built-in | Say "review the unpushed commits on main instead" (`git log origin/main..HEAD`). Check `/help` once | (E), walkthrough 2 |
| Expo Go on the iPhone updated itself and no longer opens the project mid-slice | The store app moved to a newer SDK (about 3 SDKs a year, so SDK 59 around early 2027 (E)) | Tag the last `good-` state, then in a fresh session ask Claude to upgrade with the `expo:expo-upgrade` skill, then `npm run check` and `npm run test:e2e` | (E), pre-mortem |
